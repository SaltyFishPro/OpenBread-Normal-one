# SD 字库读取与真实帧缓冲验证

此工具在电脑上编译生产 `SdFontFile`、`SdFontCacheBuffer`、`SdBitmapFont`、`SdBitmapText`、`SdFontTestPage`、共享标题、ST7305 驱动及 U8g2，读取真实 NBFT 文件。用独立 Python 读取器产生参考字形和图像，核对 C++ 的读取结果与帧缓冲像素。

## 运行

需要 Python 3.10+、`uv` 和 Windows 的微软雅黑（合览标题使用 `C:/Windows/Fonts/msyh.ttc`）。仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/sd_font_tests/build.ps1
```

先用 [字体工具](../font_builder/README.md) 导出 `font-14.bin`、`font-20.bin`、`font-24.bin` 到默认 `tools/font_builder/output/`，或指定路径：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/sd_font_tests/build.ps1 -FontDirectory 'D:/MyFonts/output'
```

默认数据为用户导出的思源旧字形 Normal，覆盖中文、拉丁字母和“𠮷”。其他字体的缺字会按生产占位框策略比较。脚本通过 `uv` 使用 Zig 0.13.0 编译和 Pillow 比较图片，不修改 PlatformIO 环境。字体与生成文件均不入 Git。

## 输出与覆盖范围

输出位于 `tmp/sd-font-test/`：

- `sd-font-framebuffers.png`：三个字号的测试页合览，各页来自真实 384×168 生产帧缓冲，按最近邻放大。
- `page-14.png`、`page-20.png`、`page-24.png`：单页原尺寸。
- `checking.png`、`error-*.png`、`no-card.png`：等待与异常画面；`render-*` 等图片用于像素核对。
- `test.exe`、参考字形和损坏文件夹：主机测试产物，源字库不受修改。

自动验证包括：

- 三份实际 BIN 的文件头、CRC、字形度量、点阵字节、空格、测宽与扩展区码点。
- 四种旋转、负坐标、裁剪、白色墨迹和缺字框；三字号合计 18 组与 Python 参考图逐像素比较。
- 额外以同样三份字库和最多 7500 条 NBCI 运行 18 组像素核对，每种内存模式合计 36 组。当前用户导出的 7080 字索引若存在，会逐字比较三个字号全部常用字的度量与点阵，不修改源输出。
- 校验每 tick 的 32KiB 上限、4ms 时间预算、模拟慢卡和计时回绕、检查中取消、关闭后不再读文件；缓存命中及缺字命中不重复读卡。
- 同次会话中切回已校验字号不重扫 NBFT payload：无 NBCI 时只读 64 bytes 文件头，有 NBCI 则额外重新加载/校验该索引，不重复查询 SD 容量与根目录。整页样张重绘读取 0 bytes。OK 重试、重新进入、文件头变化和 NBFT I/O 错误使校验记录失效。
- 65,537 条索引、32 位二分查找、超缓存字形按行读取、旧会话字形拒绝。
- 截断、错误文件头、字号不符、CRC 损坏、字形偏移/补位错误、文件读取失败及重试；文件句柄关闭和字号双向循环。
- PSRAM 模式与无 PSRAM 回退模式分别运行，均核对 18 组像素。模拟分配失败、连续空闲块不足、内存预算、切换字号复用分配、异常/退出/析构释放和同组缓存冲突覆盖。
- 连续 256 个汉字的两轮工作集，统计文件 `read()` 次数，确认有限索引缓存和字形缓存减少访问；该比较不包含完整 CRC，也不是实机耗时测试。
- NBCI 文件头版本/大小、字号、字库绑定、空/超限条数、保留位、长度、CRC、码点/顺序/对齐/范围损坏都回退普通查找；跨加载块边界也检查严格顺序。目标偏移虽合法却指向另一码点时，当前查询回退并停用索引。
- 索引未完全校验前不可启用。32KiB/4ms、慢卡与计时回绕、NBFT 正文恰好在 32KiB 边界、取消/OK 重试/切换字号、重新加载与句柄/内存释放均覆盖；可选文件 I/O 错误回退，真实字库文件 I/O 错误释放资源。
- 分布在常用字索引中的 256 个字符，从空字形缓存各查询一次，对比带/不带 NBCI 时的文件读取次数；比较不含完整字库 CRC 或索引加载成本，不能当作实机倍速。

2026-10-21 性能优化后：上述用例通过，18 组像素比较通过。`sizeof(SdBitmapFont)` 在主机编译为 10,968 bytes，较 8 槽字形缓存版本增加 9,224 bytes。这是主机结构大小，ESP32 资源占用应以完整固件构建为准。

2026-10-22 有限缓存：主机 `sizeof(SdBitmapFont)` 为 2,048 bytes，另按需申请 119,168 bytes 外部缓存，低于 128KiB 预算。两种模式均通过像素及行为检查；256 个码点两轮查询共读取 282 次（PSRAM）/6,672 次（内部 8 槽回退），PSRAM 第二轮 0 次。统计只对应本工作集，不代表所有文本的命中率或实际倍速。记录为 `tmp/sd-font-psram-host-20261022.log`。

2026-10-22 NBCI 接入后：主机服务大小 2152 bytes，外部峰值 125,792 bytes（7500 常用字记录区、256 字形槽、64 索引块）。两种模式各通过 36 组像素比较；本机现有导出为三个字号各 7080 常用字，其全部点阵与度量通过。256 个分散常用字单轮查询的读取次数为普通查找 817 / 常用索引 511，均从空字形缓存开始，不含完整 CRC 或 NBCI 加载；仅支持判断本工作集的读取减少。当前没有 NBCI 的连续 256 字两轮为 365 / 内部回退 6672 次，外部模式第二轮为 0；缓存划分改变后不沿用旧版的命中率结论。记录 `tmp/sd-font-common-host-20261022.log`。完整固件编译通过：静态 RAM 97,744 bytes（29.8%）、Flash 3,960,471 bytes（54.0%）；动态 PSRAM 单独计算，未烧录。

## 验证边界

`FS.h` / `SD_MMC.h` 使用电脑只读文件代替真实 SD；物理挂载由 `SdCardService::refresh()` 的测试替身提供。`Arduino.h` 在共用预览替身上提供可控时钟，文件读取可注入延迟以检查预算；切换测试卡时显式 `end()` 模拟会话失效。`esp_heap_caps.h` 替身使用主机内存模拟外部堆，记录申请、释放及峰值；它不证明目标板实际剩余 PSRAM 或访问速度。显示缓冲布局、旋转及绘制沿用生产驱动，Arduino/SPI 接口使用主机替身。

工具未运行完整 `UiManager` 或自检父页面，不能用此结果替代实际返回路由、GPIO16 切换、SD_MMC 时序、热拔卡、屏幕残影和功耗验收。父页面退出清理与 SD 交接路径另做代码检查，实机清单见 [SD 点阵字库](../../docs/SD_BITMAP_FONTS.md)。涉及生产代码修改后仍须完整 `pio run`。
