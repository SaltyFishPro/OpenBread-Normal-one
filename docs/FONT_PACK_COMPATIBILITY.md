# V0.1.9 字体资源兼容

固定 UI 使用 3500 常用汉字及既有界面补充字符，共 3611 个码点，三个字号清单一致。
完整字体保留，动态内容的使用边界不变。输入来源和固定规则见
[清单说明](../tools/font_builder/charsets/README.md)。

## 加载与资源

14-ui 按 8KiB 顺序读、CRC 校验、分步解析，全部常用字缓存完成后关闭文件；
当前缓存 274,436 bytes。UI 缓存预算单独为 384KiB，临时输入最多 512KiB。
20/24-ui 沿用按需分步加载和常驻 NBFT，单份最多 512KiB。
普通完整字体缓存仍限制为 128KiB，没有扩大完整字库的缓存。
三份当前字库文件为 183,807 / 285,946 / 325,805 bytes。
14-ui 常驻加 20/24 常驻共 886,187 bytes 动态 PSRAM，临时输入另计。
冷启动需要更多读取，实际时长应以 `[FONT] ui ready ... elapsed_ms=...` 和
`ui resident ... verify_ms` 相关日志测量；主机模拟耗时不等于实机启动时间。

## 兼容行为

新固件不再要求 UI 包字数等于当前固件需求字数。旧小包和含额外字符的扩展包可以读取。
14 号只在初始化阶段从完整字库补齐缺字，绘制不做临时读卡。
20/24 号若旧包缺少当前 UI 字符，回退完整字体，保留有界缓存；这一路径仍可能读 SD，
首次完整字体 CRC 和缺字查询可能增加等待。完整字体本身没有该字时使用原有占位框。
完成的缓存可用于睡眠与 SD 转 USB；取消、会话失效和 PSRAM 不足仍按原错误路径回收。

首次开机对子集检查基本格式、字号、文件大小边界，不再绑定发布包的精确字数和 CRC。
运行时加载仍校验 payload CRC 和记录；下载的新文件仍核对编译清单的 SHA-256。
完整字体继续绑定当前完整字体的大小、字数和 CRC，不任意接受陌生字体。

## 发布与服务器

运行 `python tools/font_builder/build_ui_package.py`，生成三个子集、固件下载清单和
`tools/font_builder/output/normal-one-fonts-ui-common-v1.zip`，ZIP 内含 `Font/`。
服务器须在以下目录放置六份字体文件：

`/opt/openbread-ota/data/ota/openbread-normal-one/Font/`

公开下载地址为 `https://ota.openbread.net/ota/openbread-normal-one/Font/`。
更新该固定目录的文件后清理 CDN 缓存，确保大小和 SHA-256 与固件清单一致。
旧固件若仍绑定旧版子集哈希，无法下载替换后的新子集；固定服务器路径本身不改变旧固件的校验规则。
本地代码和包生成不会自动上传服务器。V0.1.9 可继续使用旧 SD 内容；
建议更新常用字包以获得顺序读取和离线缓存路径。
