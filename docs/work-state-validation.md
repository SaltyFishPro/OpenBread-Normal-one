# 任务状态与待机验证

本次修正把“页面显示的结果”与“服务是否还在工作”分开。主界面仍在空闲 20 秒后尝试浅睡，其他页面仍不自动浅睡。

## 本次行为

| 情况 | 是否要求高频处理 | 是否阻止主界面浅睡 |
| --- | --- | --- |
| OTA 正在连接、检查、下载、校验或应用 | 是 | 是 |
| OTA 已是最新版、有更新、下载完成待应用、失败且任务已结束 | 否 | 否 |
| 音乐正在打开或播放 | 是 | 是 |
| 音乐暂停，尚未达到原有一分钟断电时间 | 否 | 是，继续运行断电计时 |
| 音乐已挂起或已停止 | 否 | 否 |
| 音乐播放失败，解码和音频电源已关闭 | 否 | 否 |
| 音乐目录仍在扫描或音频电源尚未释放 | 不额外申请音频高频 | 是 |
| 蓝牙栈仍开启 | 是 | 是 |
| 蓝牙超时或初始化失败，栈已释放 | 否 | 否 |

“不要求高频”指该服务不再申请高频。页面绘制、其他无线任务或硬件自检仍可让 CPU 保持 240 MHz；尤其音乐播放页暂停后的连续重绘，本次没有改变。暂停计时、恢复播放位置、音量和原有按键方式保持一致。

## 串口检查

工作状态改变时输出一次：

```text
[POWER] ota_busy=0 audio_realtime=0 music_busy=0 bt_active=0
```

- `ota_busy`：OTA 是否还有实际任务。
- `audio_realtime`：是否需要持续音频处理。
- `music_busy`：是否仍有播放、暂停断电计时、扫描或音频电源占用。
- `bt_active`：蓝牙栈是否还开启。

通过 `OB_POWER_WORK_LOG_ENABLED=0` 可关闭这组日志。已有 `[CPU]` 日志的理由位：`0x01` 为绘制，`0x02` 为音频，`0x04` 为无线，`0x08` 为自检。服务原因释放后，如果还在 240 MHz，应结合理由位判断，不能只看频率。

## 实机步骤

1. **OTA 正常结束**：检查更新，等到“已是最新版”或“有新版本”，确认 `ota_busy=0`。按 Left 返回主界面；图标停止及绘制高频窗口结束后，应能回到 80 MHz，最后一次操作约 20 秒后出现 `[SLEEP] enter home auto-sleep`。按键唤醒后能继续切换菜单。
2. **OTA 检查失败**：让设备连接不到路由器，等检查超时；确认 `ota_busy=0`，返回主界面后同样可以浅睡。恢复网络后重新检查应仍能发起任务。结果保留，不会为释放忙碌状态而清除“有更新”或“待应用”的信息。
3. **音乐正常操作**：播放一首正常音频，应有 `audio_realtime=1`；暂停后应为 `audio_realtime=0 music_busy=1`。一分钟后看到暂停断电日志及 `music_busy=0`；再按 OK 应恢复播放，重新出现 `audio_realtime=1`。检查音量、切歌和 Left 返回。
4. **音乐失败恢复**：选一个不能解码的测试文件，失败时应有 `[AUDIO] playback failed; decoder stopped, power off`，随后 `audio_realtime=0 music_busy=0`。能再选正常文件播放，退出音乐后主界面仍能浅睡。
5. **蓝牙超时**：开启蓝牙后不连接，等一分钟超时，确认 `bt_active=0`。返回主界面可浅睡；再次进入蓝牙功能仍能开启广播。

不需要改变硬件引脚或总线配置。本次复用已有音频停止、静音和电源关闭流程，未更改外设初始化。
