# SD 卡点阵字库

## 当前状态与使用

固件已能按需读取 `tools/font_builder` 生成的 NBFT v1 单色字库，支持 32 位 Unicode 码点、四字节 UTF-8、基线偏移和透明绘制。测试入口为 **设置 → 设备自检 → SD字库测试**；2026-10-24 增加 **阅读 → 单词阅读 → 词库 → 单词释义** 试点。阅读页只迁移释义正文，其他文字与页面保留内置字体；尚未裁减完整内置字库。

2026-10-22：测试页接入有限 PSRAM 缓存，总预算 128KiB；阅读试点复用同一服务和缓存，不另建一份。接入常用字索引后，固定申请 **125,792 bytes（约 122.8KiB，占 8MiB 的 1.50%）**，包含最多 7500 条常用字索引、256 字形槽与 64 索引块。缓存当前字号的部分数据，不整体加载字库；首次 CRC 校验仍会读取整份 payload，不能用缓存命中效果推断首次等待已消除。音乐页尚未接入，不据此宣称音乐并发读取已经通过。

电脑端工具支持选择常用字 TXT，导出与每个字号匹配的 `font-字号.common.bin`（NBCI v1），并整理出可整包复制的 `Font/`。固件在完整字库校验通过后，检查同目录的 NBCI 文件头与绑定关系，再分步加载其正文到现有预算内。查询顺序为 **字形缓存 → 内存中的常用字索引 → 完整字库二分查找**。7500 条索引文件为 60,096 bytes，其中正文 60,000 bytes 驻外部 RAM；不缓存整套常用字点阵。索引可选，缺失、损坏、字库不匹配、超过上限或外部 RAM 不足时自动回退。需烧录对应新固件，真实速度仍待设备验证。操作见 [工具说明](../tools/font_builder/README.md#常用字-txt-与快速索引)，字段见 [索引格式](../tools/font_builder/FORMAT.md#nbci-v1-常用字索引)。

将工具导出的整个 `Font/` 复制到 SD 卡根目录：

```text
SD 卡根目录/
  Font/
    font-14.bin
    font-20.bin
    font-24.bin
    font-14.common.bin   # 可选；与对应字号成套复制
    font-20.common.bin
    font-24.common.bin
```

`Font` 是当前约定目录。文件名与文件头中的字号必须一致，不能通过改名转换字号。`manifest.json` 可留作电脑端核对，但固件不解析它，也不依赖它查找字库。

进入自检测试页默认打开 14 px；`Up/Down` 循环选择 14、20、24 px，`OK` 刷新 SD 状态并重新完整检查当前字号，普通或长按 `Left` 关闭文件、卸载 SD 并返回自检列表。检查期间同样可以切换或返回。标题、操作和错误提示使用内置字体，因此字库不可用时仍可操作。

样张包含中文、标点、英文、数字、重音字符，以及扩展区字符“𠮷”（U+20BB7）。能否显示某个字符取决于源字体是否提供该字形；缺字显示占位框。当前不做字距配对、复杂文字塑形、双向排版、变体序列或彩色 Emoji。

## 阅读页试点（2026-10-24）

`ReaderPage` 只在用户打开词库成功后调用共享 `SdBitmapFont.open(14)`，库列表、单词大标题、音标、底栏和等待/错误提示继续使用内置字体。SD 根目录至少需要 `/Font/font-14.bin` 和对应 `/words/*.txt`；`font-14.common.bin` 可选，20/24 号文件不用于本试点。沿用原词库格式：一条一行，`单词<TAB>音标<TAB>释义` 或 `单词<TAB>释义`，UTF-8。原有释义字段为 512 bytes（含终止符），本次不扩容；截断的 UTF-8 按替换字符处理。

正文区域为 x=3…350、y=42…142，避开标题、底栏与右侧箭头。按实际字形 advance 换行，词性标记保持另起一行；按文件行高决定每页行数，最多保留当前页 8 个字节跨度。当前 14 号导出行高 27 px，显示 3 行。只在切词、翻页或重试时重新排版，每轮最多处理 16 个码点、处理后达到 4ms 即让出；单次字形查找中的阻塞读取仍可能超出预算。稳定页面不重复测宽和分页；绘制阶段若缓存未命中仍可能读卡，未承诺完全无 I/O 的渲染。

## 模块与调用顺序

| 模块 | 职责 |
| --- | --- |
| `bsp/SdFontFile` | 只读文件、定点读取与边界检查，不负责挂载 |
| `bsp/SdFontCacheBuffer` | 有预算限制的外部 RAM 分配/释放，不向内部堆申请大块内存 |
| `services/SdBitmapFont` | 文件头、CRC、Unicode 索引查询、度量与缓存，不绘图 |
| `ui/SdBitmapText` | UTF-8 解码、测宽、基线绘制、裁剪和缺字框 |
| `ui/pages/SdFontTestPage` | 三个字号的选择、重试、样张与错误展示 |
| `ui/pages/ReaderPage` | 单词释义的分步排版、分页、裁剪与错误重试 |
| `DeviceSelfTestPage` / `UiManager` | 返回路由、挂载会话、分步推进和 SD 所有权切换 |

使用顺序：

1. 关闭旧字库句柄，确保 GPIO16 为 LOW，再通过现有 `SdCardService` 挂载 SD。
2. `font.open(14)` 检查文件头和长度；此前未校验的 NBFT 进入 `Checking`，同次测试会话中完整文件头匹配可复用其完整 CRC 结果。每次打开都重新读取/校验当前字号的可选 NBCI，通过或回退后进入 `Ready`。返回成功时仍需查看状态，不能以 NBFT 复用结果推断已就绪。
3. 主循环调用 `font.tick()`，仅 `Ready` 时可以查字或绘制；`consumeChanged()` 用于触发状态变化后的重绘。
4. `SdBitmapText::measureUTF8()` 按字形进位测宽；`drawUTF8()` 接收左侧笔位置、基线及裁剪矩形，写入现有帧缓冲。背景由调用页面先清理。
5. 退出或更换 SD 所有者前先 `font.end()`，再卸载 SD；不可先卸载后继续使用旧字形对象。

`Glyph` 带有会话编号，重新打开后旧会话字形不能用于读取。页面退出、进入「SD卡转USB」和休眠卸载 SD 前均调用 `end()`，关闭文件、释放外部缓存并清除已验证记录。只在用户进入字库测试或打开阅读词库时打开文件，不启动后台扫描；CRC 检查或释义排版时临时提速及 1ms 协作轮询，完成后释放该请求并恢复普通调度。阅读返回不主动卸载共享 SD，以保留原有音乐后台播放语义。

## 资源与格式边界

- 文件头 64 bytes，索引记录 24 bytes；全部按小端字段解析。详细定义见 [NBFT v1](../tools/font_builder/FORMAT.md)。
- 首次打开每份文件时校验完整 payload CRC32。NBFT 校验、NBCI 文件头与 NBCI 正文加载分别推进；每次 `tick()` 最多读取 32 KiB，4ms 后让出。NBFT 使用 1024-byte 栈缓冲，NBCI 按最多 128 条记录/块直接读入固定外部缓存。时间预算在每次读卡与处理后检查，单次阻塞读取可能超过预算。完整 CRC 与全部记录检查通过之前不启用常用字索引。
- 保存最多三份通过校验的完整 64-byte 文件头。相同文件头（含长度、CRC、字号与度量）在本次测试会话中复用结果，打开仍重新检查文件头和长度。切换字号复用现有挂载，不重复查询容量、已用空间和根目录；无卡或按 OK 时刷新 SD 状态。
- `end()`、任何文件/字形错误、重试或重新进入测试均使校验记录失效。调用方必须在卸载、换卡、USB 切换或其他字库写入前先 `end()`；不允许跨挂载会话沿用记录。外部若在同一会话中改变 payload 却保留整个文件头，单靠文件头匹配无法检测，需主动重试或重新进入来执行完整检查。
- 以 uint32 码点查询，不整体加载文件或完整 NBFT 索引。PSRAM 固定一次分配：7500×8 bytes 的常用字正文区、64 个索引块（每块 16 条记录、384 bytes 数据及位置标签）与 256 个字形槽（每槽 128 bytes 点阵及字形信息）。相较上一轮 512 槽/96 块方案，在相同总预算内为常用字保留空间；无常用字索引时也使用此布局，不代表所有文本的命中率都优于旧版。索引块按块号映射，字形采用每组 4 槽的有限查找和覆盖，不随文本增长扩容；缺字同样缓存。切换字号清空旧状态并复用分配。
- NBCI 必须完整绑定当前 NBFT 的 64-byte 文件头，码点合法且严格递增，字形记录绝对偏移在 NBFT 索引区、按 24-byte 对齐并严格递增；正文 CRC 必须通过。查询命中后核对目标记录码点，不符即停用该 NBCI、当前查询回退完整字库。加载阶段不再次随机读取全部常用字目标。可选索引错误不会使已校验的完整字库进入错误状态；真正的 NBFT I/O 或字形错误仍关闭文件、释放资源并提示重试。
- 分配使用 `MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT`，申请前检查最大连续外部空闲块；PSRAM 不可用、连续块不足或分配失败时，回退到内部 8 槽字形/1 块索引缓存并跳过 NBCI，不把大块申请转移到内部 RAM。静态小缓存仍随服务常驻，外部缓存在退出、重试、NBFT 错误时立即释放。NBCI 完成/不可用后立即关闭其文件，仅 NBFT 句柄保持打开；加载时最多两个句柄，返回/切换关闭二者。初始化、查字及绘制中不反复申请内存。
- 超过缓存容量的字形按行读取；单字宽、高上限均为 1024，绘制栈缓冲为 128 bytes。小字体不要求固定的 `字号×字号` 点阵。
- 检查文件头、长度、CRC、所访问记录的码点/标志/范围、点阵长度及行末补位。设备不再遍历验证全部索引排序与连续性，依赖导出工具完成结构验证；CRC 也不是签名认证。
- 无卡、缺文件、字号不符、损坏或读取失败均有提示，可按 OK 重试。错误会关闭文件并清理缓存。拔卡后已缓存字形可能仍能绘制，直到下一次实际文件访问才报告读取失败，不宣称即时检测热拔卡。
- 帧缓冲绘制遵守当前屏幕旋转和页面裁剪。`measureUTF8()` 使用进位而非墨迹包围框；换行使用文件记录的行高。

当前用户导出使用 `SourceHanSansOLD-Normal-2.otf`、阈值 110，每份包含 44,650 字符，其中 2,495 个位于 U+FFFF 以上；配套常用字索引收录 7080 字，各 56,736 bytes：

| 字号 | 文件大小 | 上升部 / 下降部 / 行间隔 | 行高 | 最大单字点阵 |
| --- | --- | --- | --- | --- |
| 14 px | 2,252,839 bytes | 18 / 8 / 1 | 27 px | 52 bytes |
| 20 px | 3,300,565 bytes | 27 / 11 / 2 | 40 px | 76 bytes |
| 24 px | 3,958,525 bytes | 32 / 14 / 3 | 49 px | 92 bytes |

这些数据只对应当前源字体和导出参数。未来替换全局字体前，需重新检查各页面的基线、测宽、行高和缺字策略；不能直接用字号代替行高。

## 硬件与日志

沿用现有 **SD_MMC 1-bit**：CLK=GPIO11、CMD=GPIO12、D0=GPIO10。`BoardConfig` 中 MISO/MOSI 是旧别名，此处没有改成 SPI。GPIO16 LOW 时由设备读卡，HIGH 时转给板载 USB-to-SD 芯片；不能在电脑持卡期间同时访问 SD。

字库日志前缀为 `[FONT]`，记录打开路径、通过后的字号/字符数/长度与 `verify_ms` 校验等待耗时，复用时显示 `CRC32=reused`；失败时记录阶段。缓存初始化记录 `cache=psram`、实际 bytes、预算与槽数，分配失败显示 `cache=internal`，退出记录索引/字形命中和未命中计数及释放。计数反映查询命中，不能当作耗时或物理 SD 扇区访问量。添加编译宏 `OB_SD_FONT_LOG_ENABLED=0` 可关闭。挂载日志继续由现有 SD 服务提供。实际 SD 挂载、路由切换和退出后的恢复需在目标 PCB 验证。

常用字索引日志为 `common=loading`、`common=ready size=14 count=7080 index_bytes=56640 cache_bytes=125792`（当前导出示例），或 `common=off reason=...; full-font lookup`。退出统计 `common_hit` / `miss` 只包含字形缓存未命中后进入常用字查询的次数；常用字已在字形缓存时不重复计入。未命中常用字集合不是错误。
