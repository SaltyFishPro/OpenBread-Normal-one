# OpenBread 设备自检详细设计

## 1. 文档目标

本文定义设置菜单中“设备自检”功能的可实施方案，覆盖页面结构、状态机、模块职责、硬件测试步骤、功耗策略、日志和验收标准。

实现必须遵守同目录下的 `PROJECT_OUTLINE.md`：

- 保持 `App Core -> Services -> BSP Drivers` 的依赖方向，UI 只负责表现与交互。
- 主循环保持非阻塞，测试流程使用 `millis()` 推进，不在页面逻辑中执行长阻塞操作。
- 不使用无必要动态内存；测试结果使用固定容量结构。
- `Up/Down` 只移动焦点或翻页，`OK` 进入或确认，`Left` 返回。
- 外设仅在用户启动对应测试后上电，测试结束、取消或超时后立即释放。
- 所有 UI 固定使用中文，并按 384 x 168 横屏可视区域检查文本边界。

## 2. 功能范围

设置菜单新增一个“设备自检”入口，进入后提供：

1. 快速自检
2. 屏幕测试
3. 按键测试
4. IIC 设备测试
5. RTC 测试
6. SD 卡测试
7. 音频测试
8. 马达测试
9. IMU 测试
10. 无线测试
11. 电源测试

第一阶段优先实现屏幕、按键和 IIC 设备测试。其他测试保留清晰接口，按本文后续阶段逐项落地。

“快速自检”只执行无需人工确认、不会修改用户数据、不会启动无线的项目。屏幕、按键、音频、马达和 IMU 动作测试必须由用户参与。无线和 SD 写入必须由用户单独确认，不允许静默执行。

## 3. 当前硬件与实现基础

### 3.1 屏幕

- 设备：2.9 寸 ST7305 单色反射屏。
- 原始尺寸：168 x 384，当前旋转参数为 `BoardConfig::kDisplayRotation = 1`。
- 接口引脚：SCLK GPIO2、SDIN GPIO1、CS GPIO3、DC GPIO4、RST GPIO46、TE GPIO45。
- 可复用模块：`DisplayMonoTft`、`Render1bpp`。

### 3.2 按键

| 语义 | 引脚 |
|---|---:|
| Left | GPIO0 |
| Right | GPIO14 |
| Up | GPIO17 |
| Down | GPIO21 |
| OK | GPIO18 |

按键为 `INPUT_PULLUP`，低电平表示按下。现有去抖时间为 25 ms，Left 长按阈值为 650 ms。

### 3.3 IIC 总线

- 当前命名为 `IIC`，实际代码使用 Arduino `Wire`，即 I2C 主机模式。
- SDA GPIO47，SCL GPIO48，扫描频率 100 kHz。
- 传感器电源由 GPIO6（`kPinSensorLdoEn`）控制；SDA/SCL 上拉由 ESP32-S3 侧电源提供，不依赖该 LDO。为保证板上 I2C 外设本体供电，系统初始化时默认开启该 LDO。
- 可复用模块：`IicBusScanner`、`IicScanService`。
- 当前自检扫描范围为 0x03 至 0x77，由 `IicScanService::tick()` 每轮探测一个地址，不使用 `delay()` 阻塞 UI。

### 3.4 其他外设

- RTC：`RtcDriver`，与 I2C 共用 GPIO47/GPIO48；RTC 直接接电池，不依赖音频或传感器 LDO。
- SD：1-bit SD_MMC，CLK GPIO11、CMD GPIO12、DATA0 GPIO10。
- 音频：PCM/I2S 数据 GPIO40、LRCK GPIO39、BCK GPIO41，并使用音频 LDO GPIO38、XSMT GPIO5、NS 控制 GPIO13、耳机检测 GPIO15。
- IMU：`ImuDriver` 当前能力需要在实施前确认并补齐芯片识别接口。
- 马达：`MotorDriver` 使用 GPIO42（`kPinDrvEn`）作为 DRV2605L 的 EN 控制脚；EN 高电平有效，系统初始化时配置为输出并拉低，默认关闭马达驱动。震动测试功能仍需在驱动完成后接入。
- 电量计：MAX17048，I2C 地址 0x36；读取 VCELL、SOC、CRATE、VERSION 和 STATUS。

音频 DAC 和马达当前不能假定为 I2C 设备。IIC 自检只报告总线上实际响应的设备。

## 4. 架构与文件归属

建议新增：

```text
src/
  services/
    DeviceSelfTestService.h
    DeviceSelfTestService.cpp
  ui/pages/
    DeviceSelfTestPage.h
    DeviceSelfTestPage.cpp
```

现有文件调整：

```text
src/ui/pages/SettingsPage.h/.cpp   添加“设备自检”菜单入口
src/ui/UiManager.h/.cpp            路由输入、切换页面、统一 tick/render
src/bsp/*                          只在缺少最小硬件检测接口时补充
src/bsp/BoardConfig.h              仅存放确定的引脚和设备地址常量
```

### 4.1 UiManager

只承担以下职责：

- 从设置菜单进入或退出自检页面。
- 将按键事件路由给 `DeviceSelfTestPage`。
- 每轮调用 `DeviceSelfTestService::tick(nowMs)`。
- 服务状态变化时设置 `needsRedraw_`。
- 页面退出时调用 `cancel()`，保证外设释放。

不得在 `UiManager` 中编写具体测试步骤或判断硬件结果。

### 4.2 DeviceSelfTestPage

负责：

- 自检菜单、单项测试页和结果总览的中文显示。
- 将按键转换为“选择测试、确认人工结果、取消”等页面语义。
- 屏幕测试图案的绘制。
- 按键测试中的按下反馈。

不得直接调用 `Wire`、SD_MMC、I2S 或 GPIO 电源控制。

### 4.3 DeviceSelfTestService

负责：

- 管理自检会话和测试状态机。
- 调用已有 Service 或 BSP 接口执行检测。
- 保存固定容量测试结果、错误码和耗时。
- 控制超时、取消和资源回收。
- 输出统一串口日志。

服务不直接绘制屏幕，也不决定页面坐标。

### 4.4 BSP

BSP 只提供原始能力，例如：

- I2C 单地址探测、设备寄存器读取。
- RTC 原始读取。
- SD 挂载、读取和可选临时文件测试。
- IMU 芯片 ID 与原始采样。
- DAC 启停及固定测试音输出接口。
- 马达固定时长脉冲。

具体“通过/失败”规则由 `DeviceSelfTestService` 判断。

## 5. 固定容量数据模型

建议使用以下语义，不要求字段名完全一致：

```cpp
enum class SelfTestItem : uint8_t {
  Display,
  Buttons,
  IicBus,
  Rtc,
  SdCard,
  Audio,
  Motor,
  Imu,
  Bluetooth,
  Wifi,
  Power,
  Count
};

enum class SelfTestStatus : uint8_t {
  NotRun,
  Running,
  Passed,
  Failed,
  NeedsConfirmation,
  Skipped,
  Cancelled,
  Unsupported
};

struct SelfTestResult {
  SelfTestStatus status = SelfTestStatus::NotRun;
  int16_t errorCode = 0;
  uint32_t durationMs = 0;
  uint32_t detail = 0;
};
```

结果数组固定为 `SelfTestItem::Count`，禁止使用动态容器。`detail` 用位图或计数承载轻量信息，例如按键通过位、I2C 设备数量或 SD 容量摘要。较长显示文本由页面根据状态和错误码生成，不在服务中保存 `String`。

## 6. 服务状态机

```text
Idle
  -> Preparing
  -> Running
  -> WaitingForUser
  -> Passed / Failed / Skipped / Unsupported
  -> Releasing
  -> Idle
```

批量快速自检增加 `RunningSequence`，每项完成后推进到下一项。任何状态收到取消请求都先进入 `Releasing`，完成资源回收后才能回到 `Idle`。

建议接口：

```cpp
bool begin();
void tick(uint32_t nowMs);
bool start(SelfTestItem item, uint32_t nowMs);
bool startQuickTest(uint32_t nowMs);
void cancel();
bool submitUserResult(bool passed);
SelfTestStatus status(SelfTestItem item) const;
const SelfTestResult& result(SelfTestItem item) const;
bool isBusy() const;
bool consumeChanged();
```

`start()` 只登记请求，不在调用栈中执行长操作。每个测试必须定义超时；超时后记录错误并释放对应资源。

## 7. 各测试详细实现

### 7.1 屏幕测试

该测试属于人工确认项目，软件不能读取物理面板像素。

图案顺序：

1. 全白
2. 全黑
3. 1 像素外边框和中心十字线
4. 横向黑白条纹
5. 纵向黑白条纹
6. 8 x 8 棋盘格
7. 中文字号、数字和符号样张
8. 全屏刷新动态图形移动并显示刷新率在右下角。

交互：

- `Up/Down`：切换图案。
- `OK`：完成全部图案后进入“正常/异常”确认。
- `Left`：取消并返回自检菜单。
- 每个图案左下角显示当前序号、测试项名称和 `Up/Down` 切换提示。
- 第八项持续全屏刷新移动图形，并在右下角显示最近一秒的实际刷新率。

绘制要求：

- 使用显示宽高动态计算边界，不散落 384 x 168 硬编码坐标。
- 图案必须覆盖四角和边缘，以发现裁剪、方向和行列驱动异常。
- 前七项只在图案变化时刷新；第八项不设置软件帧率上限，由主循环在显示提交完成后立即准备下一帧。实际帧率仍受 SPI 与屏幕全帧刷新速度限制。
- 结果为 `NeedsConfirmation`，用户确认后变为 `Passed` 或 `Failed`。

验收：无越界、无非预期残影，文字完整，黑白和方向正确。

### 7.2 按键测试

进入页面时清空五个按键的通过位。页面显示五个固定按键区域，按下时反白，检测到一次可靠的按下与释放后设置对应通过位。

建议位定义：

```text
bit0 Left
bit1 Right
bit2 Up
bit3 Down
bit4 OK
```

关键交互处理：

- 自检页必须获得原始去抖后的按下和释放事件，不能让 Up/Down 同时移动普通菜单焦点。
- 五个短按全部通过后自动显示完成状态。
- Left 在测试中作为被测按键，普通短按不会退出；长按 Left 取消测试。
- 全部按键通过后按 `OK` 返回测试列表。
- 页面复用 `UiManager` 已去抖的稳定按键状态，不直接读取 GPIO；每个按键必须在测试页内完成一次按下和释放才记为通过。
- 检测某按键持续低电平超过 10 秒时标记“疑似卡键”，但允许用户取消。

验收：每个实体键均能独立点亮并记录，不误触发页面切换，不因按键自动重复而重复计数。

### 7.3 IIC 设备测试

当前实现复用 `IicScanService` 的固定容量结果结构，并采用非阻塞步进：每次 `tick()` 探测一个地址，地址间不使用 `delay()`。扫描范围保持 0x03 至 0x77。

检测流程：

1. 用户按 OK 启动。
2. 打开传感器 LDO，并非阻塞等待 100 ms。
3. 初始化 GPIO47/GPIO48、100 kHz I2C 主机。
4. 非阻塞逐地址扫描，记录最多 16 个地址、溢出数和错误数。
5. 根据 BSP 提供的预期地址表判断缺失设备和未知设备。
6. 保留共享 Wire 会话并恢复测试前的传感器电源状态；后续 RTC、MAX17048 或再次扫描可直接复用总线。

结果规则：

- 总线初始化失败或 SDA/SCL 异常：`Failed`。
- 必需设备缺失：`Failed`。
- 必需设备齐全但存在未知地址：`Passed`，同时显示提示。
- 预期地址尚未在 BSP 中确认：只显示扫描结果，状态为 `NeedsConfirmation`，不得把“发现任意设备”视为通过。

页面显示：SDA/SCL、频率、扫描进度、发现地址、预期设备名称、缺失设备和错误响应数。

日志前缀统一使用 `[SELFTEST][IIC]`，错误使用 `[ERR][SELFTEST][IIC]`。禁止逐个打印所有无响应地址，只打印开始、发现设备、异常和最终摘要。

### 7.4 RTC 测试

流程：

1. 复用已经初始化的 `RtcDriver`，只读访问设备地址 `0x51`，不重新调用会清除 `STOP` 位的 RTC 初始化接口。
2. 读取 `Control_1`（00h）、`Control_2`（01h）、`Offset`（02h）、`Timer_mode`（11h）以及 Seconds 的 `OS` 标志。
3. 读取第一次日期时间，校验年、月、日、时、分、秒和星期字段范围。
4. 由 `RtcTestService` 非阻塞等待约 1100 ms，再读取第二次时间并确认秒值递增。
5. 根据寄存器只读判断运行状态与省电配置，不自动修改任何寄存器。

RTC 测试页面分为两页：第 1 页只显示日期时间、字段有效性和走时结果；第 2 页显示关键寄存器、OS 状态与省电建议。使用 `Up/Down` 在两页之间切换，底部显示当前页码。

运行失败条件：RTC 地址无响应、寄存器读取失败、日期时间字段非法、`STOP=1` 导致时间停止，或两次读取之间时间没有递增。

RTC 直接接电池，不受音频或传感器 LDO 控制。驱动初始化时将 `CONTROL_2.COF` 设置为 `111`，关闭 CLKOUT；RTC 自检只读取状态，不改变时间或业务配置。

配置建议条件：

- `EXT_TEST=1`：外部时钟测试模式仍开启。
- Seconds 的 `OS=1`：振荡器曾停止，当前时间可信度不足。
- `COF[2:0] != 111`：CLKOUT 仍输出时钟，驱动初始化时会关闭该输出。
- `MI/HMI`、`TE` 或 `CIE` 开启：提示确认周期中断、倒计时器或校准中断是否确有用途。
- Timer 未使用但 `TCF[1:0] != 11`：建议选择 1/60 Hz 低功耗源。
- Offset 的 `MODE=1`：快速校准模式可能增加功耗，建议在无需快速修正时使用 `MODE=0`。

`AIE` 不作为省电异常，因为闹钟中断可能是产品的正常唤醒来源。`CAP_SEL` 只显示原始配置，必须在确认晶振负载电容是 7 pF 或 12.5 pF 后才能判断，不能凭软件默认值宣告错误。自检不得写入时间、执行软件复位、清除标志或更改闹钟与校准配置。RTC 与 IIC 自检运行期间必须暂停常规 RTC 周期读取，避免共享 `Wire` 冲突。

若 RTC 中断引脚 GPIO7 的硬件行为尚未确定，本阶段不把 INT 引脚电平作为通过条件。

### 7.5 SD 卡测试

默认只读测试：检测插卡、挂载、文件系统、总容量和可用容量，并读取根目录首个可访问条目。未插卡应显示“未插入”，不等同于硬件损坏，可记为 `Skipped`。

可选写入测试必须二次确认：

- 使用固定名称的临时文件和少量固定数据。
- 写入后立即读回并校验。
- 无论成功、失败或取消都尝试删除临时文件。
- 不扫描整个 SD 卡，不修改用户媒体文件。

测试退出时调用 `SdCardService::end()`，除非音乐或阅读功能仍明确持有 SD 会话。

当前实现采用默认只读流程：按用户进入测试时挂载 1-bit SD_MMC，检查卡类型、总容量、已用/可用容量，并打开根目录确认文件系统可读。页面不创建、修改或删除任何文件；退出测试时卸载 SD 会话。

### 7.6 音频测试

音频测试必须由用户按 OK 启动：

1. 打开音频 LDO。
2. 初始化 DAC/I2S。
3. 以安全低音量播放 500 至 1000 ms 固定提示音。
4. 停止 I2S、静音 DAC、关闭音频 LDO。
5. 让用户选择“听到/未听到”。

耳机检测 GPIO15 可作为附加状态显示，但不能代替听音确认。测试不得加载 SD 音乐文件，建议使用固定生成波形，避免把 SD 故障误判为音频故障。

### 7.7 马达测试

在 `MotorDriver` 完成前状态必须显示 `Unsupported`。驱动完成后，用户按 OK 才执行一次不超过 300 ms 的短振动，随后立即关闭驱动并让用户确认。

必须设置硬性停止时间，即使页面退出或状态异常也不能保持驱动使能。日志记录开始、持续时间和停止结果。

### 7.8 IMU 测试

分两步：

- 静态检查：读取芯片 ID，采集固定数量样本，检查全零、固定值和明显越界。
- 动作检查：提示用户翻转或轻晃设备，确认至少一个轴变化超过合理阈值。

传感器以现有 20 ms 周期采样，不在 UI 帧中循环读取。系统初始化时保持传感器 LDO（GPIO6）开启，以保证共享 I2C 外设供电；QMI8658A 未使用时只关闭其测量模块，不关闭 GPIO6。

当前硬件型号为 QMI8658A。`ImuDriver` 在 BSP 层探测 0x6A 和 0x6B，要求 `WHO_AM_I=0x05`。系统启动后写入 `CTRL7=0x00`，关闭加速度计和陀螺仪但保留 I2C 访问能力；进入自检时写入 `CTRL1=0x60`、`CTRL2=0x26`、`CTRL3=0x56`、`CTRL7=0x03`，随后读取从 0x35 开始的 12 字节原始数据。`ImuTestService` 以 20 ms 周期持续采样；超过 25 组后，数据非全零且检测到动作变化时自动标记通过，但通过后继续检测，不自动暂停。页面分为两页：第 1 页显示检测状态、芯片地址和芯片标识，第 2 页持续显示加速度与陀螺仪六轴原始值；使用 `Up/Down` 翻页。用户按 Left 退出或测试结束后写回 `CTRL7=0x00`，GPIO6 保持开启。

当前配置假设：加速度量程 8g、陀螺仪量程 512 dps、125 Hz ODR、400 kHz I2C。`CTRL7=0x00` 是未使用 IMU 时的低功耗配置；实际待机电流、寄存器复位值和数据输出必须在目标 QMI8658A 与实际 PCB 上验证。

### 7.9 无线测试

无线测试默认不进入快速自检。

- BLE：短暂初始化并广播，显示初始化和广播结果，最长 10 秒。
- Wi-Fi：只扫描附近网络，不保存凭据、不自动连接。
- 网络连通性：仅在用户主动选择并已有凭据时进行，可检查 DNS 和 HTTPS。

完成、失败、取消或超时后必须停止扫描、断开连接并设置 `WIFI_OFF`。无线会话需要与 OTA、配网和蓝牙遥控互斥，已有会话存在时提示用户先退出对应功能。

### 7.10 电源测试

本项仅执行只读电源诊断，不包含睡眠测试。用户进入页面时执行一次检测，按 OK 可重新读取。

检测内容：

- 通过 `Max17048Driver` 读取地址 0x36 的 VERSION、VCELL、SOC、CRATE 和 STATUS。
- 电池配置为单节高压锂电池：标称 3.8 V、满充 4.35 V、额定容量 800 mAh；充电管理芯片为 BQ24078。
- 将 VCELL 转换为毫伏，将 SOC 转换为百分比，将 CRATE 转换为每小时百分比变化率；根据 800 mAh 容量估算剩余容量和充放电电流。
- 正常检测电压范围设为 3000 至 4400 mV，SOC 允许至 105%。低于或高于范围时显示低压或过压警告。
- 剩余容量与电流是根据 SOC/CRATE 计算的估算值，不是库仑计或采样电阻的直接测量结果。
- 只读显示音频 LDO GPIO38 与传感器 LDO GPIO6 当前使能状态。LDO 开启或关闭本身不判定为故障，因为状态取决于当前业务场景。

`Max17048Driver` 位于 BSP，只负责寄存器访问和单位换算；`PowerDiagnosticService` 负责电池参数换算、合理性判断和统一 `[SELFTEST][POWER]` 日志；页面分两页展示电池信息和芯片/LDO 信息。测试不切换 LDO、不进入睡眠、不重启设备，也不持续轮询。传感器 LDO 常开会增加待机功耗，这是当前为保证 RTC/MAX17048/IMU 供电稳定而采用的硬件兼容策略。

BQ24078 未发现已接入 BSP 的 PG/CHG 状态引脚，因此当前测试不能直接判断充电器输入有效、正在充电或充电完成。MAX17048 的 RCOMP 与温度补偿参数依赖具体电芯特性，不能仅根据 3.8 V、4.35 V 和 800 mAh 推导，本测试保持只读，不写入未经电芯数据确认的配置。

## 8. 快速自检定义

第一阶段快速自检建议顺序：

```text
IIC 总线 -> RTC -> SD 只读 -> 内存摘要
```

后续 IMU 驱动稳定后可加入芯片 ID 和静态采样。快速自检不执行屏幕图案、按键等待、声音、振动、无线和 SD 写入。

批量测试遇到失败时继续执行后续安全项目，最终展示汇总；仅在总线卡死、供电异常等可能影响后续测试的情况下提前终止。

## 9. UI 信息架构与交互

导航保持：

```text
设置 -> 设备自检 -> 测试列表 -> 单项测试/结果
```

任何单项测试最多两次 Left 返回主菜单，符合 `PROJECT_OUTLINE.md` 的三层导航约束。

测试列表每项显示名称和短状态：`未测试 / 测试中 / 通过 / 失败 / 待确认 / 不支持`。使用反白表达焦点，不依赖灰阶。列表超过五项时沿用现有分页逻辑，页码必须与焦点同步。

列表底部不显示上、下箭头，只在右下角保留页码。用户继续使用 `Up/Down` 移动焦点和跨页，不额外增加方向提示，避免底部视觉拥挤。

### 9.1 测试列表左右布局

设备自检页面使用左右分区：

- 左侧显示当前页最多五个测试选项，并使用反白框标识焦点。
- 右侧显示当前焦点对应的功能简介。
- 左右区域之间保留固定间距，可使用一条竖向分隔线增强层级，但不使用卡片嵌套。
- 焦点移动时只更新简介内容，不改变页面结构，不触发任何硬件测试。
- 简介固定为三行，每行使用预先确定的短文本，禁止运行时自动换行。
- 简介区域必须使用固定坐标和裁剪边界，最长文本也不能覆盖左侧菜单或右侧页码。

### 9.3 文案显示规范

- 右侧不重复显示选项标题，避免与左侧焦点项重复占用空间。
- 正文只使用中文字体、黑色文字和白色背景，不使用灰阶。
- 三行文本垂直居中于内容区，行距固定，焦点变化不能引起布局跳动。
- 不显示“按 OK 开始”等操作提示，直到对应测试功能实际接入。
- 当前纯 UI 阶段，按 `OK` 不改变页面、不显示成功或失败状态。
- 页码固定显示在右下角，简介区域必须为页码预留空间。

结果总览只显示摘要和失败项，不把长串诊断文本塞入一页。详细错误通过选中失败项进入详情查看。

## 10. 资源、电源与并发约束

- 自检服务只保存固定结果数组和少量硬件状态，不创建后台任务。
- 屏幕静止时不持续重绘；仅状态、按键或测试图案变化时刷新。
- 同一时刻只运行一个测试，避免共享 I2C、电源或无线资源冲突。
- 音频 LDO 必须采用“测试前记录状态、按需打开、结束后恢复”的所有权策略，不能无条件关闭其他功能正在使用的电源。当前传感器 LDO（GPIO6）因 RTC、MAX17048 与 QMI8658A 共用板级供电策略保持开启；IMU 通过 `CTRL7=0x00` 关闭未使用的测量模块降低功耗。
- 无线测试结束立即关闭无线。
- SD 测试不遍历完整目录，不建立大型索引。
- 串口日志通过 `OB_SELF_TEST_LOG_ENABLED` 控制，发布版本可关闭。

## 11. 错误码与日志

建议按测试项分段定义固定错误码：

```text
100-119 屏幕/用户确认
120-139 按键
200-239 IIC 总线与设备
240-259 RTC
300-329 SD
400-429 音频
430-449 马达
500-529 IMU
600-639 无线
700-739 电源与睡眠
```

日志示例：

```text
[SELFTEST] start item=IIC
[SELFTEST][IIC] bus ready SDA=47 SCL=48 clock=100000
[SELFTEST][IIC] found address=0x51
[ERR][SELFTEST][IIC] required device missing address=0x00
[SELFTEST] finish item=IIC status=failed error=203 duration_ms=248
[SELFTEST] release item=IIC sensor_power=on
```

错误日志必须说明失败阶段和关键测量值，正常 tick 不刷屏。

## 12. 分阶段实施计划

### 阶段 A：框架与前三项测试

- 新增 `DeviceSelfTestService` 和 `DeviceSelfTestPage`。
- 设置菜单加入“设备自检”。
- 实现固定容量结果模型和通用状态机。
- 实现屏幕图案、五键测试、非阻塞 I2C 扫描。
- 增加取消、超时、资源释放和日志。

### 阶段 B：板载基础外设

- 实现 RTC 两次读取验证。
- 实现 SD 只读检查和可选写入检查。
- 补齐 IMU 芯片识别与静态/动作采样。
- 建立 I2C 预期设备表；地址必须来自确认后的硬件资料或 BSP 常量。

### 阶段 C：人工感知与高功耗测试

- 补齐马达驱动并实现限时振动。
- 实现固定低音量测试音。
- 实现 BLE/Wi-Fi 可选测试及会话互斥。
- 完成 MAX17048 电量、电压、变化率和芯片状态的只读诊断。
- 显示音频与传感器 LDO 当前使能状态，不在测试中切换供电。

### 阶段 D：稳定性与量产收口

- 增加快速自检汇总和错误详情。
- 验证取消、超时、连续重测和异常断电路径。
- 记录最近一次结果时，应使用小型固定结构和原子写入；默认不频繁写 Flash。
- 完成长时间运行、SD 拔插、I2C 缺设备、卡键和无线失败回归。

## 13. 验收清单

- 设置菜单能进入设备自检，原有菜单索引与业务入口没有错位。
- Up/Down、OK、Left 行为符合全局约束，测试页不会误触发普通导航。
- 屏幕测试覆盖全屏边缘、黑白、线条、棋盘格和中文样张。
- 五个按键均能检测按下与释放，存在明确的取消方式。
- I2C 扫描不会长时间阻塞主循环，能区分总线失败、设备缺失和未知设备。
- 每个硬件测试具备统一前缀日志、错误码、超时和资源释放路径。
- 无线、音频、传感器和马达只在用户触发后启用，结束后立即关闭或恢复原状态。
- SD 默认只读；写入测试必须确认并清理临时文件。
- MAX17048 通信失败与数值异常能明确区分，按 OK 可重新检测。
- 电量、电压和变化率换算需与实测仪表及已知电池状态交叉核对。
- 所有页面固定中文，文字不越界，不破坏现有 1bpp 风格和转场。
- `pio run` 编译成功，并在交付时记录 RAM/Flash 占用。

## 14. 实机验证边界

编译只能验证接口、状态机和资源链接，以下内容必须在目标 ESP32-S3 与实际 PCB 上验证：

- 屏幕坏点、残影、方向和 TE 行为。
- 五个实体按键的电平、去抖和卡键判定。
- I2C 上拉、供电时序、实际设备地址和总线恢复。
- RTC 走时、IMU 数据、SD 拔插、耳机检测、DAC 输出和马达动作。
- 无线射频表现、休眠电流和唤醒来源。

在硬件型号、I2C 地址或电源有效电平未确认前，对应项目必须显示“不支持”或“待确认”，不能用默认假设给出“通过”。
