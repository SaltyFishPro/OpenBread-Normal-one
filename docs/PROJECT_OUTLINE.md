# OpenBread Normal One 项目大纲（ST7305 单色反射屏）

> 更新于 2026-10-24。本文件同时承担**目标架构与开发规范**、**当前实现对照**两项职责。第 2～14 节描述后续开发应遵循的设计方向；标有“当前实现”的内容才表示已落地。新增功能先检查所属层级、交互与资源约束，再更新实现状态。目标设备为 ESP32-S3 N16R8，屏幕逻辑分辨率为 384×168。

## 1. 项目目标
- 目标设备：2.9寸单色反射式 TFT（1-bit，黑白两色，无亮度控制）便携设备。
- 核心功能：设置、音乐、阅读、专注时钟、无线功能、闹钟及轻量工具；未实现的入口见第 15 节。
- 硬件资源：SD 卡、陀螺仪(IMU)、RTC 芯片、马达驱动芯片、DAC。
- 系统要求：高可维护、低耦合、可扩展、非阻塞主循环、UI 风格统一。

## 2. 总体架构
- 架构分层：`App Core -> Services -> BSP Drivers`，UI 独立为表现层。
- 驱动层（BSP）：只负责硬件访问，不包含业务规则。
- 服务层（Services）：封装业务逻辑，向上提供统一接口。
- UI 层：只处理页面、组件、交互反馈，不直接操作底层硬件。
- 应用核心（App）：负责启动和系统状态编排；事件总线和统一调度器是后续架构方向，不应仅因预留头文件存在就视为已启用。

当前实现：`App` 初始化串口与 `UiManager` 并转发 `tick()`；页面状态和导航主要由 `UiManager` 编排，业务状态由对应页面与 Service 承担。未来若迁入 App Core，须保持模块职责边界，不把页面业务搬进 `App`。

## 4. 核心设计原则
- 实时优先：所有主路径满足可预测时延，输入与告警链路优先级最高。
- 非阻塞执行：禁止 `delay()` 与长阻塞 I/O，统一使用 `millis()` 任务调度与状态轮询。
- 工具链约定：构建、烧录与串口监视统一使用 PlatformIO CLI（`pio`）命令，不以 `python -m platformio` 作为默认入口。
- 明确时序预算：为 UI、输入、IMU、存储、音频分别定义周期与最大执行时长预算。
- 中断最小化：ISR 只做置位/入队，不做复杂逻辑、不访问慢速外设、不动态分配内存。
- 内存确定性：关键路径避免堆分配，优先静态内存、固定容量缓冲区与对象池，防止碎片化。
- 功耗可控：支持 `Active/Idle/Sleep` 功耗状态，外设按需上电，空闲时降频或休眠。
- 故障可恢复：外设初始化失败可降级运行（如无 SD 进入只读内建模式），并支持热重试。
- 数据安全：配置写入采用原子更新（临时文件+校验+替换），防止掉电损坏。
- 可观测性：统一日志分级与事件追踪，关键故障保留最小诊断信息（重启原因、错误码、时间戳）。
- 硬件抽象隔离：业务与 UI 不直接依赖芯片寄存器，全部经 BSP 接口访问，便于换型与测试。
- 接口稳定：跨层通信使用小而稳定的数据结构与事件协议，减少模块间隐式耦合。
- 可测试可量产：关键服务具备仿真或回放入口，启动自检覆盖显示、存储、IMU、RTC、马达、DAC。

## 5. App Core 设计
以下是目标接口和时序规范。当前 `AppState.h`、`EventBus.h`、`Scheduler.h` 只有类型或小工具定义，主运行路径没有接入完整状态机、事件总线或统一调度器；当前实际导航状态见 `UiManager::UiState`。
### 5.1 状态机（AppState）
- `Boot`：上电初始化。
- `Home`：主菜单与导航。
- `Reader`：阅读功能页。
- `Music`：音乐功能页。
- `Alarm`：闹钟功能页。
- `Remote`：无线遥控页。
- `Settings`：设置页。
- `Sleep`：低功耗待机。
- `Error`：错误处理与恢复。

### 5.2 事件总线（EventBus）
- 事件类型：`Input`、`Timer`、`RtcAlarm`、`ImuGesture`、`SdMounted`、`AudioState`、`Navigation`。
- 事件载荷：固定小结构体（type + 参数），避免堆内存分配。
- 分发策略：主循环内轮询分发，确保线程模型简单稳定。

### 5.3 任务调度（Scheduler）
- 输入扫描：`10ms`。
- IMU 轮询：`20ms`。
- UI tick：`33ms`（约 30fps 逻辑刷新）。
- 闹钟检查：`1000ms`。
- 存储刷写：后台低频（避免频繁写入）。

## 6. UI 与渲染框架（单色屏专项）
### 6.1 本章总结
- UI 采用 `主菜单 -> 子菜单 -> 详情页`；单条目工具可由主菜单直达详情页，返回路径仍须确定。
- 主菜单采用纵向滚动列表，中心固定矩形焦点框，菜单内容上下移动。
- 强制使用单色屏友好策略：1bpp、脏区刷新、低闪烁、高对比。
- 主菜单到子菜单必须使用统一过渡动画，形成稳定的产品识别感。

### 6.2 信息架构
- 主菜单（Home）：当前有设置、音乐、阅读、专注时钟、无线功能、游戏、闹钟、课程表、Api统计板、答案之书、今日抽签、电脑状态看板、SD卡转USB 13 个入口；已实现内容与占位状态见第 15 节。
- 子菜单（Section）：模块内功能分组与操作列表。
- 详情页（Detail）：单对象或单任务的具体操作界面。
- 导航约束：任何详情页最多两次返回到主菜单，路径必须确定且一致。

### 6.3 主菜单交互逻辑（纵向列表）
- 入口顺序以 `HomePage` 的菜单定义为准；调整顺序时同步检查页面的 `kHomeIndex` 和直达详情路由。
- 中心固定焦点框：使用完整矩形描边，焦点框本身不移动。
- 菜单项滚动：`Up/Down` 输入触发列表整体 Y 方向平移，焦点框不动。
- 焦点判定：最终停在中心的菜单项即当前焦点项。
- 循环策略：默认循环滚动，首尾无缝衔接。
- 快速输入策略：动画可被新输入打断并续动，避免排队卡顿。

当前实现对照（2026-10-06）：
- 当前代码与本节规范一致：主菜单由 `Up/Down` 输入触发，菜单项沿 Y 轴滚动。
- 当前代码与本节规范一致：焦点框为完整矩形描边样式。
- 循环滚动与“动画可打断续动”已实现。

### 6.4 主菜单状态机
- `Idle`：等待输入，当前焦点稳定。
- `Sliding`：列表上下滚动中。
- `TransitionToSection`：主菜单到子菜单过渡动画中。
- `TransitionToDirectDetail`：主菜单直达详情页时的过渡状态。
- 状态迁移：
  - `Idle + Up/Down -> Sliding`
  - `Sliding + 动画完成 -> Idle`
  - `Idle + Confirm -> TransitionToSection`
  - `TransitionToSection + 动画完成 -> 子菜单激活`
  - `Idle + Confirm（直达入口） -> TransitionToDirectDetail -> 详情页激活`

当前实现对照（2026-10-06）：
- `HomePage` 管理 `Idle / Sliding`；`UiManager` 管理 `ToSectionTransition / ToDirectDetailTransition` 等导航状态。
- 状态迁移方向与本节规范一致：`Idle + Up/Down -> Sliding`。
- 普通入口确认后进入 `Section`，直达入口确认后进入 `Detail`。
- 转场期间通过状态隔离实现输入锁定（仅转场计时，不处理主页导航输入）。

### 6.5 主菜单渲染规范
- 图层顺序：
  - 背景层（简洁纹理或几何分区，低复杂度）。
  - 菜单项层（中心项高权重，侧项弱化）。
  - 焦点框层（完整矩形描边，始终最上层）。
- 菜单项样式：
  - 中心项：图标与标题使用最高对比与最大权重。
  - 侧项：缩小或降低描边权重，避免与中心项抢视觉。
- 文本规则：
  - 标题长度超过阈值时可局部滚动显示，但不影响主滚动动画。

### 6.6 主菜单到子菜单过渡动画（重点）
- 目标原则：先主菜单退场，再子菜单入场，形成明确“离场 -> 进场”节奏。
- 触发条件：主菜单 `Idle` 状态下收到 `Confirm`。
- 当前动画总时长：`600ms`；修改时同步检查正反向分段、输入锁定和落位。
- 动画分段（正向）：
  - `0~90ms`：主菜单背景图整体向左滑出屏幕。
  - `70~500ms`：主菜单三个可见项（图标+标题）按“上 -> 中 -> 下”依次向左滑出并消失。
  - `540~600ms`：子菜单整体从屏幕下方向上滑入并落位（`y: +height -> 0`）。
- 动画曲线：
  - 退场段（背景与菜单项）使用 `ease-in`，强化起势离场感。
  - 入场段（子菜单）使用 `ease-out`，确保落位稳定。
- 图层与运动约束：
  - 背景层与主菜单项层仅做 X 轴位移；子菜单层仅做 Y 轴位移。
  - 图标与标题必须同位移、同曲线，不允许分离运动。
  - 过渡中不依赖透明度、灰度或复杂混合，仅使用 1bpp 可实现效果。
- 状态机约束：
  - 进入过渡态：`Home + Confirm -> TransitionToSection`。
  - 过渡完成：`TransitionToSection -> Section`。
  - 过渡期间输入锁定，防止重复触发与状态竞争。
- 落位与一致性：
  - 子菜单落位后再解锁输入，并激活子菜单默认焦点项。
  - 过渡结束后各层偏移量归零，避免残留位移影响后续绘制。
- 验收标准：
  - 视觉上可明确感知“背景先退、菜单项后退、子菜单再入场”。
  - 菜单项依次退场节奏清晰，不出现整块同时消失。
  - 无闪屏、无跳点、无明显残影。

### 6.6.1 子菜单返回主菜单过渡动画（倒序）
- 目标原则：返回动画严格遵循“正向转场倒序”，形成一致的视觉闭环。
- 触发条件：
  - 在 `Section` 页按 `LEFT/Back`，触发返回主菜单转场。
  - 从子菜单进入的 `Detail` 页按 `LEFT/Back` 先返回 `Section`；主菜单直达的 `Detail` 页按 `LEFT/Back` 直接返回主菜单。
- 当前动画总时长：`600ms`（与正向转场一致）。
- 动画分段（倒序）：
  - `0~200ms`：子菜单整体向下滑出屏幕（`y: 0 -> +height`，`ease-in`）。
  - `180~340ms`：主菜单三个可见项（图标+标题）按“下 -> 中 -> 上”依次从左侧滑入。
  - `300~600ms`：主菜单背景图从左侧滑入并最终落位。
- 图层与运动约束：
  - 子菜单层仅做 Y 轴位移；主菜单项与背景层仅做 X 轴位移。
  - 图标与标题必须同位移、同曲线，不允许分离运动。
  - 过渡期间保持 1bpp 高对比表现，不依赖透明混合与灰度特效。
- 状态机约束：
  - 新增/使用返回过渡态：`ToHomeTransition`。
  - 状态迁移：`Section + Back -> ToHomeTransition -> Home`。
  - 过渡期间输入锁定，防止重复触发与状态竞争。
- 落位与一致性：
  - 回到主菜单后保留离开前的焦点索引（`focusIndex`）以保持导航连续性。
  - 所有转场偏移量归零后再解锁输入。
- 验收标准：
  - 视觉上能明确感知“先子菜单离场，再主菜单项入场，最后背景归位”。
  - 无闪屏、无跳点、无明显残影。

### 6.7 视觉语言（单色反射屏）
- 仅使用黑白两色，通过反白与线条粗细表达层级。
- 统一图标网格、描边粗细、圆角半径与间距系统。
- 强对比优先，可读性优先于装饰性。
- 动效不依赖灰阶、透明和复杂混合效果。

### 6.8 渲染实现与性能预算
- 渲染模型：`1bpp framebuffer` + `dirty-rect` 局部刷新；当前 `Render1bpp` 合并脏区域，`DisplayMonoTft` 负责提交。
- UI tick：33~50ms（20~30fps 逻辑刷新）。
- 单帧预算：目标 <= 8ms（不含慢速 I/O）。
- 主菜单滚动与转场动画期间禁止触发文件系统读取与重型排版。
- 丢帧优先级：先保证焦点落位正确，再补绘侧项细节。

### 6.9 UI 模块分工
- `UiManager`：输入路由、导航状态、过渡动画、输入锁定和统一刷新；当前不是通用页面栈。
- `HomePage`：主菜单滚动状态机、焦点索引、过渡触发。
- `Render1bpp`：脏区域收集与合并；具体页面绘制在 `pages/*`，提交刷新由 `UiManager` 调用 `DisplayMonoTft`。
- `ThemeMono`：角标尺寸、间距、线宽、动画时长、曲线参数。
- `pages/*`：子菜单与详情页业务展示，不直接操作底层硬件。

### 6.10 验收标准
- 主菜单纵向滚动手感稳定，中心焦点框始终静止且识别清晰。
- 主菜单到子菜单过渡动画连续、无错位、无明显闪屏。
- 三层导航逻辑一致，返回路径可预测。
- 在目标帧率下可长时间运行，无明显卡顿与抖动。

## 7. 功能模块职责
本节既定义已存在 Service 的职责，也保留尚未实现的目标模块。服务不直接绘制页面，页面不直接承担跨页面业务和硬件协议。
### 7.0 OtaService（已落地）
- Manifest 检查：拉取并校验 `product/channel/build/version/url/sha256/size`。
- 升级判定：仅当 `remote.build > local.build` 才进入可升级状态。
- 下载流程：分块下载固件到 OTA 分区，不整包占用 RAM。
- 完整性校验：下载后执行 SHA256 全量比对，不匹配则中止。
- 应用流程：`ReadyToApply` 下用户确认后重启生效。
- 启动后核验：重启后对比目标版本并记录 post-apply verify 结果。
- 系统更新页面：`SystemUpdatePage` 负责 384×168 横屏布局、真实状态展示、内置/远端长日志分页滚动和统一确认弹窗；日志滚动只在页面可见且不处于弹窗或联网忙碌阶段时运行。
- 清单兼容：`release_note` 是旧摘要字段，`release_notes` 是可选 UTF-8 长日志；长字段格式错误时回退摘要，不阻断 OTA。

### 7.8 ComputerStatusProtocol（已落地）
- 仅在「电脑状态看板」详情页开启 USB CDC 协议会话，Left 返回时结束会话。
- `ComputerStatusPage` 负责首帧前的专属连接引导：左侧 88×88 USB 插图与右侧操作说明，握手成功后切换为等待电脑发送画面；首个完整帧通过校验后由 `UiManager` 替换整屏，Left 返回主菜单。
- 图标使用 `HomePage::computerStatusIcon()` 共享主菜单资源，进入后播放约 1 秒并停留在最后一帧；页面私有动画状态放在 `ui/pages`，`UiManager` 只负责调度与输入/转场。等待页使用完整绘制与整屏提交，静态内容相同时跳过无关事件重绘，离开页面或首帧显示后不继续播放动画。
- 接收 Studio 渲染的 384×168、1-bit 逻辑帧（8064 bytes），不在固件端重新排版电脑指标。
- Studio 已接通 CPU、内存、网速、出口 IP 城市天气与新闻标题的中文画布自动更新；移除电源信息和天气更新时间，新闻每 12 秒分段轮播。可暂停/恢复、选择 2/5 秒采集周期，只保留最新待发送画面且跳过相同自动帧；天气/新闻后台低频获取并保留离线缓存。
- 负责 HELLO/HELLO_ACK、帧分块、ACK/NAK、CRC16、重复确认和坏包恢复；使用固定容量缓冲。
- 原生 USB-Serial/JTAG 的 RX 队列为 256 bytes，握手协商最多 240 bytes 负载，确保单包 255 bytes；残缺包在 250 ms 无新字节后清理。
- 设备端仍仅接收与显示完整帧，协议能力标志为 bit 0；整帧 CRC 校验通过后由 `UiManager` 清空绘制缓冲、绘制完整黑色像素段并整屏提交，接收期间保留屏幕上的上一有效画面。
- 2026-10-11 的差分区域与局部绘制实验因实屏覆盖坐标错误、旧像素残留已撤回。软件模拟不能代替面板实际寻址与刷新效果验收；其他页面原有的区域刷新及回退约束继续遵循。
- 协议回归入口见 [电脑状态看板协议验证](../tools/computer_status_protocol_tests/README.md)。2026-10-11 回退后 COM3 完成 20 帧真实画面、5 段新闻、暂停/恢复、5 秒刷新和软件重连；用户确认方向、文字及位置正常、没有覆盖残留。完整像素图案、物理拔线恢复和长时间运行仍待验收，上位机联调记录见 [Studio 验收设计](../../NormalOneStudio/NORMAL_ONE_STUDIO_ACCEPTANCE.md)。

## 11. 性能与资源约束
- RAM 优先级：UI framebuffer > I/O 缓冲 > 业务缓存。
- 避免动态内存碎片：关键路径使用静态或对象池。
- 日志分级：`ERROR/WARN/INFO/DEBUG`，发布版本默认关闭 DEBUG。
- UI 刷新预算：优先保证输入响应，再追求动画完整性。
- 多个 `.cpp` 使用同一图标时，资源头文件只保留元数据和 `extern` 完整数组声明，数据在对应 `.cpp` 中唯一定义，避免头文件中的 `const` 数组被重复链接。`tools/gif_to_c` 默认导出配套 `.h`/`.cpp`，页面只包含 `.h`；手工列举源文件的主机预览也必须加入资源 `.cpp`。不通过删帧、改尺寸或缩减动画缓存来实现资源去重。
- RLE 动画优先按实际帧长度存储：`frameBytes == 0x8000U` 表示偏移表与连续 RLE 数据，前 `frameCount + 1` 个小端 `uint16` 是相对数据区的起止偏移。仅当数据区不超过 65,535 bytes 且扣除索引仍有收益时采用；其他资源兼容原 raw/定长 RLE。偏移表驻留 Flash，`Anim` 不增加字段，绘制时不新增分配。页面必须使用显式 `*_FRAME_COUNT`，不能由 packed 数组行数推导帧数；`&*_frames[0][0]` 仍是统一入口。现有资源迁移须保留原始游程数据、全部帧、尺寸及间隔，并逐帧验证真实帧缓冲。
- 超过 1300 bytes 小图缓存容量的 RLE 图像，使用单行缓冲与每次绘制私有的顺序游标，跨行保留当前游程，不从头重扫。缩小/裁剪只向前推进，放大时复用同一源行；结束/截断后的区域补零。游标在每次 `drawFrame` 重置，不增加常驻图像缓存、堆分配或 PSRAM 占用。该路径依赖源行按升序请求；后续若增加旋转/反向取行，须重新审查此约束。

答案之书的记录保存在页面运行态内存，重新进入页面时清空，没有 SD/NVS 持久化。记录页同时显示最多 3 条，`Up/Down` 改变反白焦点，`OK` 再问，`Left` 返回；行与卡片底边之间应保留可见留白。

SD字库测试读取 `/Font/font-14.bin`、`font-20.bin`、`font-24.bin` 及可选的同目录 `font-字号.common.bin`。首次分步校验完整 NBFT CRC，同次测试内复用完整文件头匹配的结果；NBFT 校验、NBCI 文件头与正文分阶段推进，每 tick 最多 32KiB、按 4ms 让出，轮间让出 1ms。查询先走字形缓存、当前字号的常用字索引，再回退 32 位 Unicode 二分查找，不整体加载字库。固定申请 125,792 bytes PSRAM（128KiB 预算），含最多 7500 常用字记录、64 索引块、256 字形槽；不足时回退内部 8 槽字形/1 索引块并跳过 NBCI。NBCI 校验绑定、CRC、顺序与偏移，实际命中时核对目标码点；缺失、损坏、超限或目标不符时回退普通查字。`Up/Down` 切换字号复用分配但清空缓存并重新加载 NBCI，`OK` 刷新 SD 状态及重新完整检查，普通/长按 `Left` 关闭文件、释放 PSRAM、清除校验记录并卸载 SD。主机读取与绘制核对已通过，真实 SD 速度与交互待实机验证。其他页面保留内置字体，音乐尚未接入，固件字库体积尚未减少。进入 SD卡转USB 和休眠卸载前同样先关闭字库，详细约束见 [SD 点阵字库](SD_BITMAP_FONTS.md)。

「SD卡转USB」由 `bsp/SdUsbSwitch` 访问 GPIO16，`UiManager` 编排进入/退出，`ui/pages/SdUsbPage` 只负责绘制。启动初始化 LOW；完成进入转场后清除阅读缓存，并复用音乐退出流程停止音频/扫描、关闭文件、卸载 SD_MMC，然后置 HIGH。Left 返回时先置 LOW 再退场，后续按需挂载。现有 SD 总线是 SD_MMC 1-bit（CLK=11、CMD=12、D0=10），`BoardConfig` 的 MISO/MOSI 名称为旧别名。该功能依赖板载芯片的 HIGH/LOW 路由，不通过 ESP32 实现软件 USB MSC；默认不推断电脑是否已挂载卡。页面静态显示并提示安全弹出，`[SDUSB]` 日志可通过 `OB_SD_USB_LOG_ENABLED=0` 关闭。

当前局部刷新由 `Render1bpp` 合并脏区域，`UiManager` 决定重绘时机并调用 `DisplayMonoTft` 提交；音乐导航/列表、主页时间卡片与图标等路径可按区域推送。主页面满足休眠条件时约 20 秒无操作进入 light sleep，保留画面并由按键唤醒；配网、OTA、播放等忙碌状态会限制休眠。功耗和刷新效果仍须实机测量。
