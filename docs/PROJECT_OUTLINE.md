# 项目现状与架构

本文记录当前代码结构、可见功能状态和维护边界。状态依据当前仓库代码核对，更新日期为 `2026-11-28`。详细硬件行为与验证方法以专题文档为准；旧阶段的逐次验证记录不作为当前状态。

## 项目概况

- 目标平台：ESP32-S3 N16R8。
- 显示：ST7305 单色屏，逻辑分辨率 384 × 168。
- 固件版本与 Build 的唯一来源为 `src/app/FirmwareInfo.h`；发布时同步 OTA manifest。
- 设计约束：电池供电；硬件、SD、音频与无线按需启用；结束任务后释放资源。
- 输入约定：Up/Down 移动焦点或翻页，OK 确认，Left 返回。

## 代码职责

| 目录 | 职责 |
| --- | --- |
| `src/app` | 启动、固件信息和应用级编排。 |
| `src/ui/UiManager.*` | 输入路由、页面状态切换、转场和统一渲染调度。 |
| `src/ui/pages` | 页面业务语义、页面私有状态与绘制。 |
| `src/services` | 跨页面业务服务；不直接绘制底层显示内容。 |
| `src/bsp` | 显示、SD、RTC、IMU、音频、电机、电量等硬件访问。 |
| `src/data` | 固定数据或内容资源；不承载硬件访问。 |
| `tools` | 资源生成、页面预览、主机测试及帧缓冲验证。 |

主流程当前为 `src/main.cpp -> App -> UiManager`。不要因为规划文档或预留类型存在，就假设事件总线、通用调度器或页面栈已接入运行路径。

## 维护约束

- 新逻辑放入职责对应的模块，避免把页面业务堆入 `App` 或 `UiManager`。
- 优先固定容量数据结构，避免关键路径上的无必要动态分配和阻塞操作。
- 外设、SD 与无线仅在用户触发后启用；退出、取消、超时和失败路径都要检查资源回收。
- 局部刷新和页面绘制遵循现有裁剪与坐标约定；静态内容不应无效重绘。
- 触及硬件状态时记录关键状态、失败原因和必要测量值，避免高频刷屏。
- 修改固件代码、构建配置或资源后运行完整 `pio run -e esp32s3`，报告 RAM/Flash；硬件行为另列实机验证结果。
